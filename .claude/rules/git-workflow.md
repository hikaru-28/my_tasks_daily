# Git運用

## ブランチ

- `main` は常に動く状態を保て。`main` に直接コミットするな。
- 作業は `feature/<内容>` を切って行え（例：`feature/task-crud`）。
- マイルストーン単位ではなく、レビューできる大きさで区切れ。

## コミットメッセージ

Conventional Commits に従え。1行目は日本語でよい。

```
<type>: <変更内容の要約>
```

| type | 用途 |
|---|---|
| `feat` | 機能追加 |
| `fix` | バグ修正 |
| `docs` | ドキュメント・CLAUDE.md・規約の変更 |
| `refactor` | 挙動を変えない内部改善 |
| `test` | テストの追加・修正 |
| `chore` | 依存更新、設定、ビルド周り |

例：`feat: タスクの作成・更新APIを追加`

## 原則

- 1コミット1目的にせよ。機能追加とリファクタを混ぜるな。
- 生成物（`dist/`、`node_modules/`、Prisma のクライアント出力）をコミットするな。
- `.env` をコミットするな。`.env.example` のみ追跡せよ。
- Prisma のマイグレーションファイル（`prisma/migrations/`）は**コミットせよ**。手で編集するな。
